# Equifax DocuSign field locks (75419996, a54035fe)

## Investigation (ground truth vs ticket assumptions)
Both tickets described this as greenfield work against `server/index.ts`/`server/docusign.ts`/
`EquifaxSubscriberForm.tsx`. Actual code: the Equifax "Application for Service" tabs are built in
`server/equifaxApplicationTabs.ts`. Both fields were **already pre-filled** (Industry: `'Real Estate
Sales & Rentals'`; Permissible Purpose: the full FCRA sentence, byte-identical to both tickets'
requested value) but **neither was locked** — every tab in this file uses a shared `text()` helper
that hardcodes `locked: false`, so a signer could edit either field before signing. A checked-in
test (`equifaxApplicationTabs.test.ts`) explicitly asserted `locked === false` for both — this was
not a deliberate "must stay editable" decision, just the generic per-field default never being
overridden for these two compliance-critical fields.

## Acceptance Criteria
- AC-01: Given a landlord opens the Equifax Application for Service in DocuSign, when the Industry
  field renders, then it shows "Real Estate - Real Estate Sales & Rentals" and cannot be edited.
- AC-02: Given the same envelope, when the Permissible Purpose field renders, then it shows "In
  connection with a credit transaction involving the consumer and the extension of credit to, or
  collection of an account of, the consumer, including Mortgage" and cannot be edited.
- AC-03: Given `server/equifax.ts`'s `permissiblePurposeCode: '15'` (real Equifax API call), then
  it remains unchanged — this ticket only touches the DocuSign-signed document, not the API call.
- AC-04: Given all other fields on this form (company name, address, phone, titles, etc.), then
  they remain editable exactly as before — this is a narrow fix to 2 fields only, not a blanket lock.

## PM review
Both ACs match ticket intent. Ticket 75419996's literal `value` text ("Real Estate - Real Estate
Sales & Rentals") was adopted over the pre-existing shorter string since it's the explicit,
customer-approved wording. **PM APPROVED — proceed to development.**

true, Industry value string updated) — this is a correction of a stale regression-snapshot
assertion, not a weakening of test coverage (same number of assertions, same fields covered).
