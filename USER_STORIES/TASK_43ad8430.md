# Google Maps Street View fallback (43ad8430)

## Investigation (ground truth vs ticket assumptions)
The ticket assumed this was greenfield (new server endpoint + env var). Actual code already has
`/api/street-view-check?addr=` (availability check, `{available: boolean}`) and
`/api/street-view-image?addr=` (proxied JPEG, 24h cache) in `server/index.ts`, already consuming
`GOOGLE_MAPS_API_KEY` server-side, with one existing consumer (`ListFromReportPage.tsx`, which
persists a Street View photo into `photo_urls` at property-creation time). This ticket is about a
**live** fallback (not persisted) shown wherever a property with zero uploaded photos renders
today. Reused the existing endpoints entirely — no new server code.

## Acceptance Criteria
- AC-01: Given a property with `photo_urls` empty, when it renders on the public property detail
  page, landlord's own properties list, or a tenant's match card, then a Street View image shows
  instead of the prior empty-state (gray box / gradient placeholder), labeled "Street View".
- AC-02: Given Street View has no outdoor imagery for that address (or the address is incomplete),
  then the original empty-state message still shows — no broken image, no exception.
- AC-03: Given a property WITH uploaded photos, then nothing changes — real photos always win.
- AC-04: Given `GOOGLE_MAPS_API_KEY` is unset, then `/api/street-view-check` already resolves
  `{available: false}` server-side (pre-existing behavior) — all three surfaces degrade to their
  original empty-state text automatically, no new error handling needed.

## PM review
Scoped to the three genuinely-empty-shell, uploaded-photo-driven surfaces: public
`PropertyDetailsPage.tsx` hero, landlord's own `PropertiesPage.tsx` grid, and tenant-facing
`YourMatchesPage.tsx` match cards. Explicitly excluded: `LandlordPropertyDetailsPage.tsx` (the
landlord's own upload/manage screen — a fallback there would compete with the upload CTA) and the
two admin pages (`AdminPropertiesPage.tsx`/`AdminUserDetailPage.tsx`), which already have a
deliberate, previously-PMVV-approved stock-photo placeholder convention (`PLACEHOLDER_IMAGES`) —
replacing that wasn't requested and isn't broken. **PM APPROVED.**

## Dev
- `client/src/lib/streetViewFallback.ts` (new) — `buildFallbackAddress()`, `streetViewImageUrl()`,
  and a `useStreetViewFallback(address)` hook that calls the existing `/api/street-view-check`
  and only returns a URL when Google confirms imagery exists.
- `PropertyDetailsPage.tsx` — `PropertyHeroPhoto` falls back to Street View (with a small
  "Street View" badge) before falling back to "No photos yet"; added `postal_code` to the select
  and a `fallbackAddress` field.
- `YourMatchesPage.tsx` — `MatchCardPhoto` same treatment; added `photoAddress` to `TenantMatch`.
- `PropertiesPage.tsx` (landlord's own property list) — new `PropertyGridPhoto` subcomponent
  (needed its own component so the hook isn't called conditionally inside the `.map()`), same
  fallback chain; replaced the old behavior of printing `photo_labels[0]` as filler text with a
  real image when available.
